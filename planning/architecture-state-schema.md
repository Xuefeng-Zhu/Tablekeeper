Envelope: {track:"tablekeeper",format_version:1,state:{schema_version:1,...}}. Internal versions 1–4 denote implemented stages, not an increase in public format_version. JSON arrays below remain in their specified order. Unordered entity arrays export in stable ID order except restaurants/tables/policies/occurrences/history. Numeric instants are UTC integer microseconds; date/local/offset strings remain separately persisted. Entity payloads are ordinary JSON, never class pickles, filesystem paths or source URLs.

Stage1 state fields:

- users: [{id,email,display_name,password_hash:{algorithm:"scrypt",n:16384,r:8,p:1,dklen:32,salt_b64,digest_b64}}]. Exact email unique; ID unique <=64 characters. No password field.
- tokens: [{token,user_id}]; token unique, all users existent; no expiry, multiple rows per user.
- restaurants: [{id,name,timezone,slot_minutes,reservation_duration_minutes,cancellation_cutoff_minutes,opening_hours:[{weekday,opens,closes}],tables:[{id,label,capacity}]}]. Array order is original fixture order; table membership stored per restaurant. Policy0 configuration is never overwritten.
- reservations: [{id,reference,user_id,restaurant_id,table_ids:[id],party_size,status,starts_at_local,start_us,end_us,starts_at,ends_at,created_at}]. Stage1 internal singleton sets serialize as table_id in public responses; cancelled state retained. Reference globally unique, immutable 6..12 A-Z0-9. Offset strings and UTC instants must agree; all original timestamps preserved.
- journal: [{reference,entries:[{seq,at,event,changes:[{field,from,to}]}]}]. Created seq1, actual changes only, cancel final empty changes. Seed creation timestamp assigned once at reset. Capture at=max(operation_now,last_event_at) to preserve nondecreasing order despite wall clock corrections; seq disambiguates ties. Internal, no Stage3 endpoints in S1.
- receipts: [{user_id,method,path,key,request_body,response_body}]. Complete strict parsed JSON objects, original immutable response JSON. Composite unique scope; no failure/pending rows. Response may describe older resource state and omit future fields. Do not require it to equal current reservation state or validate its body against today's policy.

Prospective SQLite schema: users(id TEXT PRIMARY KEY,email TEXT UNIQUE,payload TEXT), tokens(token TEXT PRIMARY KEY,user_id TEXT REFERENCES users), restaurants(id TEXT PRIMARY KEY,ordinal INTEGER UNIQUE,payload TEXT), reservations(id TEXT PRIMARY KEY,reference TEXT UNIQUE,user_id TEXT,restaurant_id TEXT,start_us INTEGER,end_us INTEGER,status TEXT,payload TEXT), journal(reference TEXT PRIMARY KEY,payload TEXT), receipts(user_id TEXT,method TEXT,path TEXT,key TEXT,request_json TEXT,response_json TEXT,PRIMARY KEY(user_id,method,path,key)), metadata(key TEXT PRIMARY KEY,value TEXT). Enable foreign_keys. Use indexed reservations(restaurant_id,status,start_us,end_us) for candidates; explicit table-set overlap stays in seating.py. All SQL accessed through store.py RLock. Export payloads recover complete JSON; projections/index columns are reconstructed and cross-checked, not independently editable state.

Import procedure: parse object with strict JSON; wrong recognized envelope field JSON type ->400 under S1 type rule, absent/wrong track/version/invalid state ->422. Nested structural or referential invalid state ->422. Require supported internal schema and all required version fields; reject duplicate IDs/scopes/references, unknown users/restaurants/tables, invalid hash parameters/base64 lengths, invalid token relationships, nonpositive intervals, invalid dates/zones, invalid status, inconsistent UTC/rendered instants, malformed history sequences, bad policy maps/counters/series membership/closure intervals/plans. Preserve valid historical accepted snapshots and stale/applied plans; do not revalidate accepted bookings against newer policy or current cutoff. Verify confirmed booking/closure occupancy against stored assignments, allowing policy-independent past histories. Raw request receipts must remain JSON values, not interpreted as a fresh command. Reset fixture parsing uses its separate specified validation contract.

Build migrated entity rows in a temporary validation representation without touching destination, then under lock begin transaction, delete dependent destination rows in dependency order, insert all validated replacement rows, run SQL foreign-key/invariant checks, commit. Any exception rolls back the entire destination including prior credentials/receipts. Export never mutates rows and is detached before releasing lock. Repeat unchanged import restores exactly the same logical state; generated migration additions are deterministic. IDs/hash salts/tokens/timestamps in existing fields are never regenerated. A migrated state export may contain added fields, while original response receipts stay exactly original JSON.

Migrations: S1->S2 adds only empty pair lists/normalized singleton representation. S1/S2->S3 attaches immutable fixture-policy0 to current reservations and each private journal event, sets revision=event seq, defaults no published policies/managers/series, initializes restaurant counter0 with origin_schema. S3->S4 defaults empty plans/closures. Apply ordered functions for skipped stages, validate each result. Current-version import does not re-run defaults that would overwrite fields. No backwards import promise. Required tests use actual earlier accepted executables, credentials kept private; raw exports must never be committed.
